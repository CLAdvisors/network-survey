## Personal link + one-person resend

- `GET /api/surveys/:surveyId/personal-link-permission` returns the configured minimum role and server-calculated `canReveal`, `canResend`, `canConfigure`. Default `admin` allows owners/admins to reveal; owners alone can change the org setting via `PUT` `{minimumRole}`. Each mutation has strict transactional audit.
- `POST /api/surveys/:surveyId/respondents/:respondentId/personal-link` `{purpose:"reveal"|"copy"}` returns `{link}` with `Cache-Control: no-store`; a strict audit row with only the respondent ID commits before the link is returned. Unauthorized survey/role/foreign respondent is 404. Tokens are not returned in roster/history, logged or put in audit metadata.
- `POST /api/surveys/:surveyId/respondents/:respondentId/resend` requires an `Idempotency-Key` UUID and an admin/owner. It queues exactly one eligible incomplete respondent via the existing reminder outbox; provider sends happen only in the delivery worker. A retry with the same key returns the same launch. The dashboard preserves an uncertain key in sessionStorage until a confirmed API response, then clears it for a later deliberate resend. Reminder templates, active worker, provider scope, suppression and uncertain-outcome exclusions are enforced. Every queued resend is a reminder in `/api/surveys/:surveyId/email-history`.
- Neither endpoint overrides provider suppression, an uncertain prior reminder, or the provider's own idempotency guarantee. Already accepted email cannot be recalled; a genuinely new confirmed click after a prior campaign completes is a distinct send.

## Scheduling

- `GET /api/surveys/:surveyId/delivery-schedule` reads the current schedule; `PUT` accepts `{startLocal,closeLocal,timezone,reminderEveryDays,expectedVersion}`. Local strings are `YYYY-MM-DDTHH:mm`, timezone an IANA name, cadence an integer 1–30 local calendar days. A draft launch must be future-dated, close later and within one year. Start/timezone cannot change once launched, but cadence and close can; stale version is 409. `DELETE` with `{expectedVersion}` cancels pending scheduled deliveries and fences leased deliveries under the survey provider boundary. Manual survey close cancels the schedule.
- Launch/close local times in a DST gap or overlap are rejected. Reminder wall-time in a spring gap advances to the first valid minute; in fall overlap the earlier occurrence is used exactly once. Saved UTC timestamps are exposed for verification; no browser-computed UTC is trusted.
- **Enable both** `SURVEY_DELIVERY_V2_ENABLED=true` (existing delivery) and `SURVEY_SCHEDULES_ENABLED=true` **on the API and email worker** only after dev migration/worker QA. The scheduler piggybacks on the current worker with a 15-second poll; `email_worker_control` still fences execution. Multiple workers atomically claim due schedules with `FOR UPDATE SKIP LOCKED`; claims have expiring leases, deterministic occurrence UUID keys and version/token-fenced advancement. A crash after enqueue but before advancement replays the original idempotency key. No eligible incomplete recipients skips that reminder occurrence, without a provider request. If a worker resumes after close, overdue reminders are skipped and the close occurrence runs; an overdue initial launch is never sent and the schedule completes while the untouched survey remains draft. Close is scheduled as its own occurrence, and the provider boundary refuses any scheduled delivery whose close time has passed even if a scheduler has stalled.
- Observe `survey_delivery_schedules` `status,next_due_at,lease_expires_at`, worker heartbeat/error, `survey_launches.schedule_id` and email history. With both flags enabled the worker also emits EMF every 60 seconds under `RUNTIME_METRIC_NAMESPACE` (default `NetworkSurvey/Runtime`), dimensions `Environment` and `Process=email-worker`: `OldestDueScheduleAgeSeconds`, `DueActiveScheduleCount`, `ScheduleErrorCount`. Multiple workers emit the same backlog gauges; alarm age/count using Maximum, and error count using Sum. If a scheduled occurrence is repeatedly blocked by readiness, disabled sending or a stale operator account, fix the cause; **do not manually reset ids or send through the provider**. Cancel through the audited API if the client no longer wants further sends. Existing recovery rules for uncertain provider outcomes still apply.

## Local verification (no provider I/O)

- Root monorepo `npm ci --ignore-scripts` (per-package installs can create two SurveyJS registries and spurious dashboard ranking failures). `npm test --prefix api`; `npm test --prefix dashboard -- --run`.
- Isolated PostgreSQL: `DELIVERY_TEST_DATABASE_URL=<private-disposable-DB-URL> node --test api/test/delivery-local-db.test.js`. Fresh `master-changelog.xml` ran 32/32 changesets on 2026-09-29. Local tests cover tenant-scoped audit/no token leak, dual-worker claim, cancel fencing, restart/no repeat, targeted resend replay/history and 5,000 synthetic respondents with 25 bounded insert batches. Outbox-only insert measured ~130 ms–2.2 s on a local DB (higher under parallel test load); **not an email throughput or H4 load test**. Do not point this test at dev/prod or any valuable database; it creates synthetic users and surveys.
